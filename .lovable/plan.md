# GTM: точная привязка события заявки `nadislaty_formu`

## Что есть сейчас (по вашим скриншотам)

- Тег «Form Submission» (Google Analytics: GA4 Event) с триггером «Form Submission» — срабатывает на любую отправку формы, включая неуспешную (ошибка валидации, повторный клик). Скорее всего, именно он отправлял в Google событие, которое засчитывалось как заявка.
- Триггеров на событие `nadislaty_formu` нет.
- Сайт уже отправляет `nadislaty_formu` в dataLayer только после успешного сохранения заявки (проверено 19.09 на живом сайте).

## Что делаем (в Google Tag Manager, контейнер GTM-M22KWN6S)

1. Триггеры → Создать → тип «Пользовательское событие» (Custom Event) → имя события: `nadislaty_formu` → назвать триггер «nadislaty_formu trigger».
2. Открыть существующий тег «Form Submission»:
   - проверить, что в поле «Название события» (Event Name) стоит `nadislaty_formu`. Если там другое имя — заменить на `nadislaty_formu` (именно это событие импортировано в Google Ads как конверсия);
   - снять старый триггер «Form Submission», назначить новый «nadislaty_formu trigger».
3. Отправить/опубликовать контейнер (Submit → Publish).
4. Старый триггер «Form Submission» можно удалить — больше он ни для чего не нужен (по скриншоту он используется только этим тегом).

## Проверка (делаю я после вашей публикации контейнера)

- Прогоняю на живом сайте два теста: отправка с ошибкой в телефоне (события быть не должно) и корректная отправка (в Google должен уйти запрос с событием `nadislaty_formu`).
- Тестовая заявка будет помечена ТЕСТ.

## Открытый вопрос

Если при открытии тега «Form Submission» вы не найдёте поле Event Name или оно пустое — пришлите скриншот тега, подскажу, что заполнить.
